Use **iNaturalist’s public API, then make a local CSV and PDF map**. This avoids accounts, uploads and credentials. Its website CSV export requires an account, so that button is unsuitable here. [Export guidance](https://help.inaturalist.org/en/support/solutions/articles/151000170342-how-can-i-download-data-from-inaturalist-)

I could read documentation, but live occurrence queries were inaccessible and a direct request failed DNS resolution. **No local sighting count or finished map was verified.** The following is a reproducible, unexecuted route, with a documented response example instead of an invented Blacksburg record.

1. Define “near” as 15 km from central Blacksburg, 37.2296, −80.4139. Request photographed bees, Research Grade, with observations through October 21, 2026. Start with all historical years; optionally make a second October-only layer for seasonal context. Use this [public query](https://api.inaturalist.org/v1/observations?taxon_id=630955&lat=37.2296&lng=-80.4139&radius=15&photos=true&quality_grade=research&d2=2026-10-21&per_page=200&page=1). Save each JSON response locally, incrementing `page` until `results` is empty. Record the URL, retrieval time and `total_results`; check for duplicate IDs and changing totals. API reference: [iNaturalist](https://api.inaturalist.org/v1/docs/).

2. Do not equate “bee” or “not introduced” with native. For a practical starter map, retain only **Xylocopa virginica** and **Bombus impatiens**, clearly titled “Two native bee species: photographed observations near Blacksburg.” Virginia Extension identifies the former among Virginia’s native bees; the eastern bumble bee guide covers the latter’s regional range and identification. Expand only after checking each additional species against a regional reference; keep unverified species separately. [Virginia Extension](https://ext.vt.edu/content/dam/pubs_ext_vt_edu/ENTO/ENTO-151/ENTO-424.pdf), [eastern bumble bee guide](https://www.xerces.org/sites/default/files/2018-05/12-052_01_Eastern_Bumble_Bee.pdf)

3. Retain an observation only if it has photos, public coordinates, `obscured=false`, neither `geoprivacy` nor `taxon_geoprivacy` is `obscured`/`private`, and known `positional_accuracy` ≤100 m. Null privacy settings can mean open; null accuracy means unknown and fails this precision rule. Exclude ambiguous IDs. Research Grade is a community identification status, not certainty. Review photos for obvious errors without extracting locations from backgrounds or metadata. Obscured coordinates are randomized within a large cell; never turn them into walking destinations or infer originals. [Geoprivacy documentation](https://help.inaturalist.org/en/support/solutions/articles/151000169938-what-is-geoprivacy-what-does-it-mean-for-an-observation-to-be-obscured-)

4. Create CSV columns `id,species,date,longitude,latitude,accuracy_m,observation_url,observer,data_license`. Parse `location` as latitude,longitude, then put longitude first in the CSV. Preserve each observation link and attribution. Link to photographs rather than copying them: observation and photo licenses are separate. [Licensing guidance](https://help.inaturalist.org/en/support/solutions/articles/151000175695)

5. In free QGIS, add the CSV as Delimited Text: X=longitude, Y=latitude, CRS=EPSG:4326. Reproject to EPSG:26917; draw 100 m uncertainty circles or each record’s actual accuracy radius. Label species and year. In Print Layout add legend, scale, north arrow, query date and the 15 km boundary; export PDF and save the QGIS project plus CSV. No online basemap is required. This recipe was not tested here.

The map supports learning, not an access plan: observation locations do not establish public access. Choose the walk independently on an already authorized public route. Label blank areas **“No retained photographs in this query; bee presence unknown.”** Observer effort, season, identification difficulty, licenses, privacy and precision exclusions all create gaps. Counts are photographs/observations, not bee abundance, habitat suitability or proof of absence.

It must fail this map’s taxon, photo, quality and accuracy rules. These legacy field names must not be substituted blindly into v1 parsing.
