# Frozen real-world comparison v2

All briefs are constructed realistic requests; their evidence must come from real current primary sources, not fictional packets. No client outcomes are implied.

Development: D1 and D2, one fresh native execution per baseline/current-skill arm. Diagnose actual differences before editing. Holdout: H1–H4, two independent fresh executions per baseline/final-candidate arm. Do not inspect holdout outcomes before freezing the candidate. Native collaboration, same inherited model/effort and tool authority, no overrides. Baseline uses no optional skill; skill arm reads assigned frozen Research file only. No 01/Moonshot dependency. No other optional skills, delegation, paid API, credential work, installs, accounts, external writes or device access. Separate task-owned output folders are not security sandboxes.

Each run writes answer.md and evidence.json: wall-clock start/end from clock tool when available, primary URLs actually opened and source locations supporting decision-changing claims, observed errors/access limits, exact artifacts produced, and unavailable telemetry. Retain every first result, including failures; no reroll selection. Human-readable tool evidence is worker-reported, not a complete native tool trace. Exact backend model ID/seed/token accounting are unavailable through this host; do not invent them. Record parent dispatch/completion elapsed intervals separately from worker clock measurements.

Review: anonymize arm identity and vary left/right order by pair. Reviewers get briefs, actual answers/artifacts and this rubric, not the preferred intervention or arm map. Verify decisive claims and candidate-only discoveries from primary sources. Judge source support and usefulness before style. Each run: 0–4 for each of (1) factual/claim support, (2) constraints and feasibility, (3) breadth and material alternative, (4) decisive source inspection, (5) artifact/actionability, (6) falsifiable verification and uncertainty. 0 absent/wrong; 1 major weakness; 2 usable with material gaps; 3 strong with minor gaps; 4 well-supported and complete for this brief. Record consequential errors separately; aggregate scores cannot compensate for a critical infeasible recommendation or invented evidence.

For each pair, identify only independently checked useful additions that can change a decision, reduce operating work, prevent a failure or enable an action; mere length, source count, named tools and persuasive prose do not count. Record native-only additions as well as skill-only ones. Pairwise preference: baseline materially better, baseline slightly better, tie, skill slightly better, skill materially better; reviewer writes anonymous labels instead. A material win needs a checked practical difference without an offsetting consequential failure.

Adoption criterion: publish honest win/tie/loss and usefulness findings. Retain final skill only if it adds at least one independently verified material benefit on untouched tasks without a new critical failure pattern, while disclosing losses and operating cost. This is a bounded usefulness gate, not proof of population-wide superiority. If it fails, reject unsupported edits, explain that added value remains unestablished and publish negative evidence. Stop after this frozen development/refinement/holdout round, except concrete defects or unreliable grading require narrow resolution. Never run until a desired win appears.
