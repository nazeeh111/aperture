Recommend Syncthing for routine exchange, with explicit version retention and a separate offline backup. This is a documented proposal as of October 21, 2026, not a device-tested setup.

Syncthing fits free, account-free, server-free collaboration: each person edits local Markdown offline; changes exchange when devices are simultaneously reachable. Arrange a regular overlap window with an awake Mac. Without overlapping peers, delivery waits; public relays do not store an offline mailbox. Deletions also propagate, so another synchronized copy is not a backup. [Syncthing FAQ](https://docs.syncthing.net/users/faq.html)

The official Android wrapper was discontinued and archived in December 2024. The community continuation, researchxxl/Syncthing-Fork, is active: its release page lists stable v2.1.6.0 dated October 6 and v2.1.7.0-rc.4 dated October 14. Prefer stable releases; nominate someone to monitor this separate maintainer and update channel. Release activity establishes maintenance, not an independent security audit. [Official repository](https://github.com/syncthing/syncthing-android), [fork releases](https://github.com/researchxxl/syncthing-android/releases)

Use a shared-storage notes folder on Android. Obsidian's private app storage cannot be accessed by Syncthing; shared storage requires broad file permission. Keep device-specific settings and any Git database outside the synchronized notes. The fork requires exemption from Android's sleep optimization; its hourly five-minute mode can miss an intermittently awake Mac. Start with deliberate foreground overlap sessions, checking completion before sleeping either device. Campus network isolation may require a different permitted network. [Obsidian Android](https://obsidian.md/help/android), [fork battery guidance](https://github.com/researchxxl/syncthing-android/blob/main/wiki/Info-on-battery-optimization-and-settings-affecting-battery-usage.md)

Keep three protections distinct:

- **Synchronization:** send-and-receive folders exchange current files. Assign note ownership where possible. Concurrent edits create `sync-conflict` copies; Syncthing does not merge prose. Compare both copies and reconcile manually. [Conflict rules](https://docs.syncthing.net/users/syncing.html#conflicting-changes)
- **Version history:** enable Simple Versioning on every device, for example 20 versions with automatic age cleanup disabled. Defaults retain nothing. Crucially, it archives only incoming remote replacements/deletions, never that device's own edits. A note created and deleted before reaching any peer remains unprotected. Retention consumes storage and eventually discards older versions. [Versioning](https://docs.syncthing.net/users/versioning.html)
- **Independent backup:** daily, after reconciliation, close editors, pause sync and copy the notes plus retained versions into a dated archive on existing removable storage; disconnect it afterward. Keep several generations and rotate custody. Another member's unsynchronized archive is a fallback, but a second folder on the same disk cannot survive disk loss. If no independent storage exists, that protection remains unmet. Unsaved edits and changes since the last successful copy remain at risk.

A materially different alternative is **LocalSend handoffs plus one Mac editor integrating changes**. Members edit separate offline copies, then send dated submissions into an inbox, never directly over the canonical folder. The integrator compares against each submission's named starting snapshot, merges deliberately, records local Git commits, and redistributes a dated release. Local Git needs no remote account; committed files can be recovered with `git restore --source=<commit> -- note.md`. This reduces automatic deletion propagation but adds human work and delay. LocalSend supports Android/macOS without accounts or Internet; current requirements are Android 7+/macOS 11+, with local-network/firewall access. [LocalSend](https://localsend.org/), [compatibility](https://github.com/localsend/localsend#setup), [Git restore](https://git-scm.com/docs/git-restore)

Avoid Obsidian Git as the mobile foundation: its own documentation calls mobile support very unstable, with memory limits and possible pull/clone crashes. [Plugin documentation](https://publish.obsidian.md/git-doc/Getting%20Started)

Before adoption, rehearse with disposable notes: synchronize a baseline; edit the same line offline on phone and Mac; reconnect and preserve both versions in a reconciled note. Delete a previously synchronized note on each device in turn; recover the incoming deletion's archived copy on its peer. Finally, restore the disconnected archive into a fresh folder while sync stays paused. Pass only if expected text survives, both offline edits are accounted for, and the restored folder opens independently. Repeat after substantial upgrades. None of these rehearsals was executed here.
