As of October 21, 2026, **Syncthing with explicit versioning plus a disconnected backup is the most feasible route**, provided members can periodically connect simultaneously. Everyone edits local Markdown offline; reconciliation happens later. This recommendation is a documentation-based judgment, not a tested deployment.

Use the official macOS app and the community **Syncthing-Fork**, currently maintained at `researchxxl/syncthing-android`. The original Android app was discontinued and archived in December 2024. The former Catfriend1 URL now redirects to researchxxl; its releases page lists stable v2.1.6.0 and a newer release candidate. Choose stable and assign someone to monitor updates and maintainer changes. The supported macOS v2 wrapper requires macOS 12; its README also contains an older, inconsistent macOS 11 installation sentence, so follow its explicit v2 compatibility section. [Android status](https://github.com/syncthing/syncthing-android), [fork releases](https://github.com/researchxxl/syncthing-android/releases), [macOS requirements](https://github.com/syncthing/syncthing-macos#macos-version-support).

**Synchronization:** share one ordinary notes folder through mutually approved device IDs, without accounts or a permanent server. Devices holding needed updates must overlap online; an intermittently awake laptop can carry updates between meetings. If no connected sequence carries an edit, it cannot arrive. On Android, select a folder both editor and synchronizer can access, grant the necessary storage/network permissions, and verify background operation under battery restrictions. Keep laptops awake until synchronization completes. Prefer one editor per note at a time, consistent filename capitalization, and separate device-specific editor settings. These operating rules reduce conflicts but cannot eliminate them. [Connection model](https://docs.syncthing.net/intro/getting-started.html), [online overlap](https://docs.syncthing.net/users/faq.html#what-is-syncthing).

**Version history:** enable Simple Versioning on every receiving device, for example 20 versions with no age cleanup. It is disabled by default and archives only incoming replacements/deletions, never that device’s own local edits. Retention is finite by count. Concurrent edits produce a `sync-conflict` copy rather than a semantic merge; humans must compare and combine both texts. [Versioning](https://docs.syncthing.net/users/versioning.html), [conflicts](https://docs.syncthing.net/users/syncing.html#conflicting-changes).

**Independent backup:** after each working session, save a dated archive of notes, attachments and retained versions to an existing external drive, then disconnect it. Keep several dated generations and rotate custody between members. A live replica or `.stversions` on the same disk cannot cover disk loss. Back up each member’s unsynchronized work before reconciliation; a laptop cannot protect edits it has never received. If no separate storage exists, this requirement remains unmet.

A materially different alternative is **manual LocalSend exchange plus laptop-only Git history**. Members send dated, author-labelled note copies into an inbox; a designated integrator compares them, records accepted changes in local Git, and redistributes the agreed snapshot. Never overwrite the working folder blindly. LocalSend supports Android/macOS without accounts or internet; current releases list v1.18.2. Android 7/macOS 11 are minimums; campus network isolation can prevent discovery. Direct downloads need manual updates. This sacrifices automatic convergence for explicit review. Export full Git bundles and note archives to disconnected storage. Obsidian Git’s current README explicitly discourages mobile use because of instability, memory limits and missing SSH support. [LocalSend](https://localsend.org/), [constraints](https://github.com/localsend/localsend), [Git bundles](https://git-scm.com/docs/git-bundle), [mobile warning](https://github.com/Vinzent03/obsidian-git#mobile-support-experimental).

Rehearse with disposable notes before adoption:

1. Synchronize a known note, disconnect two devices, edit the same line differently, reconnect, and combine both versions. Confirm the combined text reaches both devices.
2. Delete the note remotely, synchronize, restore its receiving-device version, and confirm propagation. Repeat a local deletion to expose versioning’s limitation.
3. With synchronization paused, restore a dated external backup into a fresh folder. Compare known contents and attachments. For the alternative, recover a committed deletion in a separate clone from its bundle. Pass only when both authors’ text and the deleted note survive. Nothing was installed or rehearsed here.
